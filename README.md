# ProcurementSystem

## ต้นแบบเวอร์ชันใหม่ (v2) — หน้าหลัก `index.html`

ต้นแบบสำหรับให้ผู้ใช้งานลองเล่นและเสนอ Function เพิ่ม (โหมดทดลอง ข้อมูลเก็บในเบราว์เซอร์ ไม่ต่อ Supabase)
เวอร์ชันเดิมยังเปิดได้ที่ `v1/` (เก็บข้อมูลแยกกัน) — เนื้อหาด้านล่างหัวข้อ "ระบบขอเบิกใช้งบประมาณ (ต้นแบบ)" อธิบายเวอร์ชันเดิม

| บทบาท (สลับที่เมนูมุมขวาบน) | ทำอะไรได้ |
| --- | --- |
| Business (สมชาย / สุดา) | สร้างร่างคำขออนุมัติงบ (แยกรายการย่อย หรือ งบรวมโครงการ) → พิมพ์แบบฟอร์มเข้าที่ประชุม → แนบมติแล้วส่งให้ผู้คุมงบ, ขอดำเนินการใช้งบ (เฉพาะงบที่ตนสร้าง), ขอเพิ่มงบ |
| ผู้คุมงบ (บัญชีการเงิน) | ยืนยัน/ส่งกลับงบและคำขอเพิ่มงบ, ตรวจคำขอดำเนินการใช้งบ (ขอเกินงบรายการต้องใส่ Note), บันทึกจ่ายเงินทดรอง / เคลียร์ / จ่ายคืนพนักงาน / จ่าย Supplier และปิดยอด, โยกงบ (ข้ามโครงการได้) / ลดงบ, นำเข้างบที่อนุมัติแล้ว |
| จัดซื้อ | บันทึก PR / PO ของใบดำเนินการใช้งบประเภท PR/PO (ตัดงบตามยอด PO) |
| Admin (อดิศร) | ข้อมูลหลัก, Log การทำงานทั้งระบบ, ผู้ใช้และสิทธิ์ (โหมดทดลองดูได้อย่างเดียว) |

- งานที่ต้องทำของแต่ละบทบาทรวมอยู่ที่เมนู **งานทั้งหมด** แยกเป็นแท็บ (ตัวเลขสีแดง = งานที่ต้องลงมือ)
- ผู้ใช้ทั่วไปดู **ประวัติการทำรายการ** ของตน (รวมสิ่งที่ผู้อื่นทำกับงบ/เอกสารของตน) — Log ทั้งระบบเห็นเฉพาะ Admin

- ประเภทการดำเนินการใช้งบ (CAPEX): ซื้อโดยเปิด PR/PO (ตัดงบเมื่อออก PO), Advance (ตัดเมื่อเคลียร์), พนักงานสำรองจ่าย (ตัดเมื่อจ่ายคืน), จ่ายตรงให้ Supplier (ตัดเมื่อจ่าย)
- ยอดจริงต่างจากที่ขอ → ปิดยอดแล้วคืนส่วนต่างเข้างบ
- ทุกการกระทำเก็บประวัติในเอกสาร และรวมไว้ที่หน้า "Log การทำงาน"
- สิ่งที่ยังรอยืนยันจากผู้ใช้งาน (ใช้ค่าเริ่มต้นไปก่อน) ดูได้ที่หน้า "สิ่งที่รอยืนยัน" (`#/assumptions`) 
- **OPEX (เดิมชื่อ CBS) ในต้นแบบ v2** ใช้ขั้นตอนเดียวกับ CAPEX ทุกอย่าง (ขอดำเนินการใช้งบ 4 ประเภท → ผู้คุมงบตรวจสอบ → ตัดงบ → ปิดยอด) ต่างกันที่การอนุมัติงบ: **ไม่เข้าบอร์ด แต่ให้ผู้บริหารอนุมัติ** — Business แนบเอกสารอนุมัติ + เลขที่ + ชื่อผู้บริหาร แล้วผู้คุมงบตรวจสอบและยืนยัน (เพิ่มงบก็เช่นเดียวกัน) ส่วนหัวข้อ "กระบวนการขอเบิกใช้งบโครงการ (CBS)" ด้านล่างอธิบายเวอร์ชันเดิม (`v1/`)

## ระบบขอเบิกใช้งบประมาณ (ต้นแบบ)

เปิดใช้งานได้ที่ `index.html` (รองรับ GitHub Pages โดยไม่ต้องมี backend) — หน้าทดสอบเดิมย้ายไปที่ `test.html`

> ระบบนี้ **ไม่ใช่การขออนุมัติงบ** — งบได้รับอนุมัติมาแล้ว ระบบใช้ **ตรวจสอบ (verify) ว่าใช้ถูกตัวงบ**
> และให้ผู้ใช้งบรู้ว่างบของตนเหลือเท่าไร

ใช้เมนู **"เข้าใช้งานในฐานะ"** มุมขวาบนเพื่อสลับผู้ใช้ตัวอย่างตามบทบาท

| บทบาท | ทำอะไรได้ |
| --- | --- |
| ฝ่ายการเงิน | บันทึก/ปรับงบที่อนุมัติแล้ว (เก็บประวัติการปรับทุกครั้ง), รับเอกสาร CAPEX แล้ว *อนุมัติ* หรือ *ไม่อนุมัติ (แจ้งเหตุผล)*, บันทึก *งวดจ่าย* (วันส่งมอบ/วางบิล, วันกำหนดจ่าย, ยอดงวด) |
| ผู้ขอซื้อ / ผู้ขอใช้งบ | ดูยอดงบของตนเอง (*งบที่ได้รับ / ใช้แล้ว / รอตรวจสอบ / คงเหลือ*) ลงลึกถึงรายการย่อย และจัดทำเอกสารขอเบิกใช้งบทุกครั้งที่จะใช้ |
| ฝ่ายบัญชี | บันทึกข้อมูลบัญชีของเอกสารที่ออกแล้ว: CAPEX แยก Asset / Expenses *รายงวด*, CBS ยืนยัน GL Code *รายบรรทัด* และสถานะจ่าย |

### ภาพรวมงบประมาณ (Dashboard) และข้อมูลหลัก
- **ภาพรวม** (ทุกบทบาท; ผู้ขอเห็นเฉพาะงบของตนเอง): กรองตามปี / บริษัท / ประเภทงบ แสดงงบที่ได้รับ ตัดงบแล้ว จองไว้ คงเหลือ
  ตารางสรุปตามบริษัท / กลุ่มงบ / หน่วยงาน / ประเภทงบ, กราฟตัดงบรายเดือน (นับเฉพาะที่บัญชีบันทึกจ่ายแล้ว),
  รายการงานที่ต้องทำตามบทบาท และงบที่เกินหรือเหลือน้อยกว่า 10%
- **ข้อมูลหลัก** (การเงิน): บริษัท, หน่วยงาน, กลุ่มงบ, ประเภทสินทรัพย์, GL Code — ใช้เป็นตัวเลือกในฟอร์มตั้งงบ (เลือก GL Code แล้วเติมชื่อ GL ให้)
  ลบค่าที่ถูกใช้อยู่ไม่ได้, รหัสแก้ไม่ได้หลังสร้าง, เปลี่ยนชื่อหน่วยงาน/ประเภทสินทรัพย์ ระบบแก้ให้ทุกงบ
  มีตาราง DOA และรายชื่อผู้ใช้/บทบาทให้ดู (อ่านอย่างเดียว)

### โครงสร้างงบ (ตามไฟล์ Excel เดิม)
- **CAPEX**: บริษัท, ปีงบ, กลุ่มงบ, *รหัสโครงการ (Project No.)* → *รายการย่อย (Item No.)* แต่ละรายการมีประเภทสินทรัพย์, หมวด DOA (2.4/2.5) และวงเงินรวม VAT
- **เงื่อนไขการทำ Memo**: เฉพาะงบ CAPEX ที่ใช้เงินข้ามบริษัทกับ PCC (งบของ PCC ที่บริษัทอื่นเป็นบริษัทที่ลงทุน หรืองบของบริษัทอื่นที่ PCC เป็นบริษัทที่ลงทุน) นอกนั้นส่งตรงให้ผู้คุมงบ · OPEX ไม่ใช้ Memo · ตั้งได้ที่ ข้อมูลหลัก > บริษัท > เกณฑ์ Memo
- **เลขที่เอกสารที่ระบบออกให้**: รูปแบบ `ตัวย่อเอกสาร-ปี ค.ศ.-ลำดับ 4 หลัก` เริ่มนับใหม่ทุกปี — `REQ` คำขอดำเนินการใช้งบ, `CAPEX` / `OPEX` ใบดำเนินการใช้งบ, `MEMO` บันทึกข้อความ, `INC` คำขอเพิ่มงบ, `TRF` โยกงบ, `DEC` ลดงบ (เช่น `CAPEX-2026-0001`) · เลขที่ฝ่ายอื่นเป็นคนออก (รหัสโครงการ / Item No. / PR / PO / เลขที่มติ / เลขที่ใบเสร็จ) ผู้ใช้กรอกเอง
- **หัวกระดาษ Memo**: โลโก้ PRECISE สีดำ (`img/logo-precise.png`) ชิดซ้าย และคำว่า Memo ชิดขวา ใช้กับทุกบริษัท · อัปโหลดโลโก้เฉพาะบริษัทได้ที่ ข้อมูลหลัก > บริษัท · ตารางหัว (เรียน/วันที่-เลขที่, เรื่อง, สำเนาถึง, อ้างอิง) กว้างกว่าเนื้อความ มีแต่เส้นแนวนอน
- **Memo แบบกรอกตามโครงเอกสาร**: กด "ทำ Memo" แล้วกรอกในหน้า Memo ที่มีช่องอยู่ในตำแหน่งเดียวกับแบบฟอร์มจริง (เรียน, วันที่, สำเนาถึง, เรื่อง, อ้างอิง, เรื่องสืบเนื่อง, เรื่องเพื่อพิจารณาลงนาม, อ้างอิงอำนาจอนุมัติ, ผู้ลงนามเสนอ, ผู้ทบทวน, ผู้พิจารณาอนุมัติ) ยอดเงินและตารางสรุประบบคำนวณจากคำขอ แล้วดูฉบับพิมพ์ / PDF
- **ใบดำเนินการใช้งบ 1 ใบใช้ได้หลาย Item** (ทั้ง CAPEX และ OPEX): เลือก Item ทีละบรรทัด ตรวจเกินงบทีละ Item และทั้งโครงการ ตัดงบตามสัดส่วนของแต่ละ Item
- **OPEX (งบดำเนินงาน — เดิมชื่อ CBS)**: ข้อมูลหัวงบกรอกเหมือน CAPEX (บริษัท, ปีงบ, กลุ่มงบประมาณ, รหัสโครงการ (Project No.), ชื่อโครงการ, หน่วยงาน, Business เจ้าของงบ) — **ต้องมี Item เสมอ**: *Item หลัก* (1, 2, 3 …) กำหนดพร้อมวงเงินตอนตั้งงบ ส่วน *Item ย่อย* (1.1, 2.1 …) เพิ่มได้หลังงบเปิดใช้แล้ว (ปุ่ม "จัดการ Item ย่อย" โดย Business เจ้าของงบหรือผู้คุมงบ ไม่ต้องอนุมัติซ้ำ ยอดงบรวมไม่เปลี่ยน) วงเงินรวมของ Item ย่อยต้องไม่เกิน Item หลัก และจะกำหนดวงเงินหรือไม่ก็ได้ (ไม่กำหนด = ใช้วงเงิน Item หลัก) · การขอดำเนินการใช้งบของ OPEX **ไม่ต้องทำ Memo** · เลขที่ใบดำเนินการใช้งบ OPEX เช่น `OPEX26-0001` (ในระบบยังเก็บรหัสประเภทเป็น `CBS` เพื่อให้ข้อมูลเดิมใช้ต่อได้)
  พร้อมจำนวน/หน่วย/ก่อน VAT/VAT/GL Code — รายการแม่รวมยอดจากรายการลูกอัตโนมัติ เบิกได้เฉพาะรายการล่างสุด
- **ปรับงบ / Revise CBS**: ทุกครั้งที่เปลี่ยนวงเงินหรือรายการต้องระบุเหตุผล และเก็บเป็นประวัติ (ครั้งที่ / วันที่ / โดย / ยอดรวม)

### กระบวนการขอเบิกใช้งบลงทุน (CAPEX)
1. ผู้ขอซื้อตรวจสอบงบที่ใช้ได้
2. จัดทำเอกสาร: รายการย่อย, วัตถุประสงค์, Supplier, เงื่อนไขการจ่าย, PO No. หรือ N/A และ **รายการที่ซื้อ/จ่ายได้หลายบรรทัด**
   (แต่ละบรรทัดมีก่อน VAT + VAT 7%) — ใบเบิก 1 ใบใช้กับรายการย่อยเดียว → ส่งให้ฝ่ายการเงิน
3. ฝ่ายการเงินรับเอกสารและตรวจสอบ
   - **อนุมัติ** → ออก *ใบเบิกงบประมาณ* เลขที่ `PSL26-001` (บริษัท + ปี + ลำดับ) → จบกระบวนการ
   - **ไม่อนุมัติ** → แจ้งเหตุผล → ผู้ขอซื้อ *แก้ไขและส่งใหม่* (ใช้เลขที่คำขอเดิม เก็บประวัติรอบก่อน) หรือ *ยกเลิก*
4. **จ่ายเป็นงวด**: ขอเบิกยอดเต็มครั้งเดียว แล้วการเงินบันทึกงวดจ่ายใต้ใบเบิกเดิมเมื่อได้รับบิล (เมนู "งวดจ่ายค้าง")
5. ฝ่ายบัญชีลงวันที่จ่ายจริงและแยก Asset / Expenses ของแต่ละงวด — เมื่อลงวันที่จ่ายงบจึงถูกตัดเป็น "ใช้แล้ว"

### กระบวนการขอเบิกใช้งบโครงการ (CBS)
1. หน่วยงานที่ขอซื้อตรวจสอบงบที่ใช้ได้ (แยกตามรายการต้นทุน)
2. จัดทำเอกสาร: วันที่เบิก, ผู้รับเงิน, PO (ไม่ออก PO ได้) และ **หลายบรรทัด — แต่ละบรรทัดเลือกรายการต้นทุนเองได้**
   → ได้เอกสารเลขที่ `CBS26-0001` ทันที (ไม่ต้องผ่านฝ่ายการเงิน)
3. **ใช้เกินงบของรายการได้ แต่ต้องระบุเหตุผล** — ยอดคงเหลือติดลบแสดงเป็นสีแดง "เกินงบ"
4. ถ้าทำเอกสารผิด ผู้ขอ *ยกเลิกเอกสาร* ได้เองโดยต้องระบุเหตุผล → ยอดคืนเข้างบทันที
5. ฝ่ายบัญชียืนยัน GL Code รายบรรทัด (ดึงจากรายการต้นทุนให้อัตโนมัติ) และบันทึกการจ่ายเงิน (สถานะ "จ่ายแล้ว" + วันที่จ่ายจริง) — จ่ายแล้วงบจึงถูกตัดเป็น "ใช้แล้ว"

### เงื่อนไขการตัดงบ
งบจะถูกตัดเป็น **"ใช้แล้ว"** ต่อเมื่อ **ฝ่ายบัญชีบันทึกการจ่ายเงินจริงแล้ว** เท่านั้น — ออกเอกสารแล้วยังไม่ใช่การตัดงบ
- **จองไว้**: คำขอที่รอการเงินตรวจสอบ และเอกสารที่ออกแล้วแต่บัญชียังไม่จ่าย — ยังหักออกจากยอดคงเหลือเพื่อกันการใช้ซ้ำ แต่ไม่นับเป็นใช้แล้ว
- **CAPEX**: ตัดงบทีละงวด เมื่อบัญชีลงวันที่จ่ายจริงของงวดนั้น (การแยก Asset / Expenses เป็นอีกขั้นหนึ่ง ไม่ทำให้ตัดงบเอง) งวดที่บัญชีลงวันที่จ่ายแล้วการเงินลบไม่ได้
- **CBS**: ตัดงบทั้งใบเมื่อบัญชีตั้งสถานะ "จ่ายแล้ว" และระบุวันที่จ่ายจริง
- เอกสารจะอยู่ในเมนู "รอบันทึกบัญชี" ของฝ่ายบัญชีจนกว่าจะจ่ายครบ

### ยอดคงเหลือ
- เอกสาร CAPEX ที่ส่งแล้วจะ **จองงบ** ทันที; ไม่อนุมัติหรือยกเลิกจะคืนยอดอัตโนมัติ
- CAPEX: ไม่ให้เบิกเกินคงเหลือของรายการย่อย (ต้องให้การเงินปรับงบก่อน)
- การเงินลดวงเงินรายการ CAPEX ให้ต่ำกว่ายอดที่ใช้/จองไปแล้วไม่ได้ และลบรายการที่มีการเบิกแล้วไม่ได้

### เอกสารผลลัพธ์
- **ใบเบิกงบประมาณ (CAPEX)** ตามแบบฟอร์มเดิม: รหัสโครงการ/รายการย่อย, ยอดงบ *ระดับโครงการและระดับรายการย่อย*
  (งบ / ใช้ไปก่อนขอเบิก / ขอเบิกครั้งนี้ / คงเหลือ), ข้อมูลการเบิกครั้งนี้ และ **ตาราง DOA ที่ระบบติ๊กระดับผู้อนุมัติตามจำนวนเงินให้**
- **เอกสารการเบิกขอใช้งบประมาณ (CBS)**: ยอดระดับ Job และยอดของทุกรายการต้นทุนที่อยู่ในใบ + GL Code รายบรรทัด
- ทั้งสองแบบแสดงตารางรายการที่ขอเบิกทุกบรรทัดพร้อมยอดรวม
- พิมพ์หรือบันทึกเป็น PDF เพื่อแนบกับใบขอซื้อ (PR)

### สองโหมดการใช้งาน
| โหมด | เมื่อไหร่ | ข้อมูล / ผู้ใช้ |
| --- | --- | --- |
| **ทดลอง** (ค่าเริ่มต้น) | `js/config.js` เว้นว่างไว้ | ข้อมูลตัวอย่างเก็บในเบราว์เซอร์ สลับผู้ใช้ตัวอย่างได้ที่เมนูมุมขวาบน ไม่มีล็อกอิน |
| **Supabase** | ใส่ `supabaseUrl` และ `supabaseAnonKey` ใน `js/config.js` | ล็อกอินด้วยอีเมล + รหัสผ่าน ข้อมูลอยู่ในฐานข้อมูลกลาง ทุกคนเห็นข้อมูลเดียวกันตามสิทธิ์ของบทบาท |

โหมด Supabase: ผู้ดูแลสร้างบัญชีที่ Supabase Dashboard แล้ว **Admin** กำหนดชื่อ/บทบาทที่เมนู **ผู้ใช้และสิทธิ์**
บทบาทตั้งต้น: Admin (จัดการผู้ใช้ สิทธิ์ ข้อมูลหลัก — ไม่อนุมัติเอกสารเอง), การเงิน, บัญชี, ผู้ขอใช้งบ
แท็บ **บทบาทและสิทธิ์** เป็นตารางติ๊กว่าแต่ละบทบาททำอะไรได้ (ดูทั้งหมด / ขอเบิก / อนุมัติ CAPEX / งวดจ่าย / จัดการงบ / บัญชี / ข้อมูลหลัก / จัดการผู้ใช้) และสร้างบทบาทใหม่ได้
สิทธิ์ทั้งหมดตรวจที่ฝั่งฐานข้อมูลทุกครั้ง และมีผลทันที
ดูขั้นตอนตั้งค่าที่ [`supabase/SETUP.md`](supabase/SETUP.md) และโครงสร้างฐานข้อมูลที่ [`supabase/schema.sql`](supabase/schema.sql)

### ข้อจำกัดของต้นแบบ
- โหมดทดลอง: ข้อมูลเก็บใน `localStorage` ของเบราว์เซอร์ จึงไม่แชร์ข้ามเครื่อง/ผู้ใช้จริง และไม่มีการยืนยันตัวตน (ใช้โหมด Supabase เมื่อจะใช้งานจริง)
- ข้อมูลตัวอย่างทั้งหมดเป็นข้อมูลสมมติ — **ห้ามนำข้อมูลงบจริงขึ้น GitHub Pages** เพราะเป็นเว็บสาธารณะ
- ยังไม่มีหน้าลืม/เปลี่ยนรหัสผ่านในเว็บ (ผู้ดูแลตั้งรหัสใหม่ที่ Supabase Dashboard) และยังไม่ได้เชื่อมเลขที่เอกสารการเบิกขอใช้งบเข้ากับขั้นตอนขอซื้อ (PR)

### ปุ่มย้อนกลับ
ปุ่ม "ย้อนกลับ" (และปุ่ม "ยกเลิก" ในฟอร์ม) พากลับไป **หน้าก่อนหน้าที่เปิดมาจริง** เช่น เปิดเอกสารจากรายการคำขอจะกลับรายการคำขอ ไม่ใช่หน้ารายละเอียด
ระบบเก็บลำดับหน้าที่เปิดไว้เอง (ไม่ใช้ history ของเบราว์เซอร์ เพราะหลังส่งฟอร์มจะพากลับไปหน้าฟอร์มเดิม) — หน้าฟอร์มจะไม่ถูกนับเป็นหน้าที่ย้อนกลับมา
ถ้าเปิดลิงก์ตรงโดยไม่มีหน้าก่อนหน้า จะกลับไปหน้าต้นทางตามชนิดหน้า (เช่น เอกสาร → คำขอ, รายละเอียดงบ → รายการงบ)

### การขึ้นเว็บเวอร์ชันใหม่
ทุกครั้งที่แก้ไขแล้วจะขึ้นเว็บ ให้เปลี่ยนเลขเวอร์ชันใน `index.html` (ใน `<meta name="app-version">` และ `?v=` ของ css/js ให้ตรงกัน)
หน้าเว็บจะเช็กเลขนี้ทุกครั้งที่เปิดหรือกลับมาที่แท็บ ถ้ามีเวอร์ชันใหม่จะโหลดหน้าใหม่ให้เอง ผู้ใช้ไม่ต้องล้าง cache
