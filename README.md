# ProcurementSystem

## ระบบขอเบิกใช้งบประมาณ (ต้นแบบ)

เปิดใช้งานได้ที่ `index.html` (รองรับ GitHub Pages โดยไม่ต้องมี backend) — หน้าทดสอบเดิมย้ายไปที่ `test.html`

> ระบบนี้ **ไม่ใช่การขออนุมัติงบ** — งบได้รับอนุมัติมาแล้ว ระบบใช้ **ตรวจสอบ (verify) ว่าใช้ถูกตัวงบ**
> และให้ผู้ใช้งบรู้ว่างบของตนเหลือเท่าไร

ใช้เมนู **"เข้าใช้งานในฐานะ"** มุมขวาบนเพื่อสลับผู้ใช้ตัวอย่างตามบทบาท

| บทบาท | ทำอะไรได้ |
| --- | --- |
| ฝ่ายการเงิน | บันทึก/ปรับงบที่อนุมัติแล้ว (เก็บประวัติการปรับทุกครั้ง), รับเอกสาร CAPEX แล้ว *อนุมัติ* หรือ *ไม่อนุมัติ (แจ้งเหตุผล)*, บันทึก *งวดจ่าย* (วันส่งมอบ/วางบิล, วันกำหนดจ่าย, ยอดงวด) |
| ผู้ขอซื้อ / ผู้ขอใช้งบ | ดูยอดงบของตนเอง (*งบที่ได้รับ / ใช้แล้ว / รอตรวจสอบ / คงเหลือ*) ลงลึกถึงรายการย่อย และจัดทำเอกสารขอเบิกใช้งบทุกครั้งที่จะใช้ |
| ฝ่ายบัญชี | บันทึกข้อมูลบัญชีของเอกสารที่ออกแล้ว: CAPEX แยก Asset / Expenses *รายงวด*, CBS ยืนยัน GL Code *รายบรรทัด* และสถานะจ่าย |

### โครงสร้างงบ (ตามไฟล์ Excel เดิม)
- **CAPEX**: บริษัท, ปีงบ, กลุ่มงบ, *รหัสโครงการ (Project No.)* → *รายการย่อย (Item No.)* แต่ละรายการมีประเภทสินทรัพย์, หมวด DOA (2.4/2.5) และวงเงินรวม VAT
- **CBS**: *Job No.* (+ โครงการหลัก), สถานะ Plan / On Progress / แล้วเสร็จ, ระยะเวลา, ข้อมูลการผลิต และ *Cost Breakdown หลายชั้น* (1 → 1.1 → 1.1.1)
  พร้อมจำนวน/หน่วย/ก่อน VAT/VAT/GL Code — รายการแม่รวมยอดจากรายการลูกอัตโนมัติ เบิกได้เฉพาะรายการล่างสุด
- **ปรับงบ / Revise CBS**: ทุกครั้งที่เปลี่ยนวงเงินหรือรายการต้องระบุเหตุผล และเก็บเป็นประวัติ (ครั้งที่ / วันที่ / โดย / ยอดรวม)

### กระบวนการขอเบิกใช้งบลงทุน (CAPEX)
1. ผู้ขอซื้อตรวจสอบงบที่ใช้ได้
2. จัดทำเอกสาร: รายการย่อย, วัตถุประสงค์, Supplier, เงื่อนไขการจ่าย, PO No. หรือ N/A และ **รายการที่ซื้อ/จ่ายได้หลายบรรทัด**
   (แต่ละบรรทัดมีก่อน VAT + VAT 7%) — ใบเบิก 1 ใบใช้กับรายการย่อยเดียว → ส่งให้ฝ่ายการเงิน
3. ฝ่ายการเงินรับเอกสารและตรวจสอบ
   - **อนุมัติ** → ออก *ใบเบิกงบประมาณ* เลขที่ `PSL26-001` (บริษัท + ปี + ลำดับ) → จบกระบวนการ
   - **ไม่อนุมัติ** → แจ้งเหตุผล → ผู้ขอซื้อ *แก้ไขและส่งใหม่* (ใช้เลขที่คำขอเดิม เก็บประวัติรอบก่อน) หรือ *ยกเลิก*
4. **จ่ายเป็นงวด**: ขอเบิกยอดเต็มครั้งเดียว แล้วการเงินบันทึกงวดจ่ายใต้ใบเบิกเดิมเมื่อได้รับบิล (เมนู "งวดจ่ายค้าง")
5. ฝ่ายบัญชีลงวันที่จ่ายจริงและแยก Asset / Expenses ของแต่ละงวด — เมื่อลงวันที่จ่ายงบจึงถูกตัดเป็น "ใช้แล้ว"

### กระบวนการขอเบิกใช้งบโครงการ (CBS)
1. หน่วยงานที่ขอซื้อตรวจสอบงบที่ใช้ได้ (แยกตามรายการต้นทุน)
2. จัดทำเอกสาร: วันที่เบิก, ผู้รับเงิน, PO (ไม่ออก PO ได้) และ **หลายบรรทัด — แต่ละบรรทัดเลือกรายการต้นทุนเองได้**
   → ได้เอกสารเลขที่ `CBS26-0001` ทันที (ไม่ต้องผ่านฝ่ายการเงิน)
3. **ใช้เกินงบของรายการได้ แต่ต้องระบุเหตุผล** — ยอดคงเหลือติดลบแสดงเป็นสีแดง "เกินงบ"
4. ถ้าทำเอกสารผิด ผู้ขอ *ยกเลิกเอกสาร* ได้เองโดยต้องระบุเหตุผล → ยอดคืนเข้างบทันที
5. ฝ่ายบัญชียืนยัน GL Code รายบรรทัด (ดึงจากรายการต้นทุนให้อัตโนมัติ) และบันทึกการจ่ายเงิน (สถานะ "จ่ายแล้ว" + วันที่จ่ายจริง) — จ่ายแล้วงบจึงถูกตัดเป็น "ใช้แล้ว"

### เงื่อนไขการตัดงบ
งบจะถูกตัดเป็น **"ใช้แล้ว"** ต่อเมื่อ **ฝ่ายบัญชีบันทึกการจ่ายเงินจริงแล้ว** เท่านั้น — ออกเอกสารแล้วยังไม่ใช่การตัดงบ
- **จองไว้**: คำขอที่รอการเงินตรวจสอบ และเอกสารที่ออกแล้วแต่บัญชียังไม่จ่าย — ยังหักออกจากยอดคงเหลือเพื่อกันการใช้ซ้ำ แต่ไม่นับเป็นใช้แล้ว
- **CAPEX**: ตัดงบทีละงวด เมื่อบัญชีลงวันที่จ่ายจริงของงวดนั้น (การแยก Asset / Expenses เป็นอีกขั้นหนึ่ง ไม่ทำให้ตัดงบเอง) งวดที่บัญชีลงวันที่จ่ายแล้วการเงินลบไม่ได้
- **CBS**: ตัดงบทั้งใบเมื่อบัญชีตั้งสถานะ "จ่ายแล้ว" และระบุวันที่จ่ายจริง
- เอกสารจะอยู่ในเมนู "รอบันทึกบัญชี" ของฝ่ายบัญชีจนกว่าจะจ่ายครบ

### ยอดคงเหลือ
- เอกสาร CAPEX ที่ส่งแล้วจะ **จองงบ** ทันที; ไม่อนุมัติหรือยกเลิกจะคืนยอดอัตโนมัติ
- CAPEX: ไม่ให้เบิกเกินคงเหลือของรายการย่อย (ต้องให้การเงินปรับงบก่อน)
- การเงินลดวงเงินรายการ CAPEX ให้ต่ำกว่ายอดที่ใช้/จองไปแล้วไม่ได้ และลบรายการที่มีการเบิกแล้วไม่ได้

### เอกสารผลลัพธ์
- **ใบเบิกงบประมาณ (CAPEX)** ตามแบบฟอร์มเดิม: รหัสโครงการ/รายการย่อย, ยอดงบ *ระดับโครงการและระดับรายการย่อย*
  (งบ / ใช้ไปก่อนขอเบิก / ขอเบิกครั้งนี้ / คงเหลือ), ข้อมูลการเบิกครั้งนี้ และ **ตาราง DOA ที่ระบบติ๊กระดับผู้อนุมัติตามจำนวนเงินให้**
- **เอกสารการเบิกขอใช้งบประมาณ (CBS)**: ยอดระดับ Job และยอดของทุกรายการต้นทุนที่อยู่ในใบ + GL Code รายบรรทัด
- ทั้งสองแบบแสดงตารางรายการที่ขอเบิกทุกบรรทัดพร้อมยอดรวม
- พิมพ์หรือบันทึกเป็น PDF เพื่อแนบกับใบขอซื้อ (PR)

### ข้อจำกัดของต้นแบบ
- ข้อมูลเก็บใน `localStorage` ของเบราว์เซอร์ จึงไม่แชร์ข้ามเครื่อง/ผู้ใช้จริง และไม่มีการยืนยันตัวตน
- ข้อมูลตัวอย่างทั้งหมดเป็นข้อมูลสมมติ — **ห้ามนำข้อมูลงบจริงขึ้น GitHub Pages** เพราะเป็นเว็บสาธารณะ
- ก่อนใช้งานจริงควรมี backend + ฐานข้อมูล, ระบบล็อกอิน, และเชื่อมเลขที่เอกสารการเบิกขอใช้งบเข้ากับขั้นตอนขอซื้อ (PR)

### การขึ้นเว็บเวอร์ชันใหม่
ทุกครั้งที่แก้ไขแล้วจะขึ้นเว็บ ให้เปลี่ยนเลขเวอร์ชันใน `index.html` (ใน `<meta name="app-version">` และ `?v=` ของ css/js ให้ตรงกัน)
หน้าเว็บจะเช็กเลขนี้ทุกครั้งที่เปิดหรือกลับมาที่แท็บ ถ้ามีเวอร์ชันใหม่จะโหลดหน้าใหม่ให้เอง ผู้ใช้ไม่ต้องล้าง cache
