# ProcurementSystem

## โมดูลขอใช้งบประมาณ (ต้นแบบ)

เปิดใช้งานได้ที่ `index.html` (รองรับ GitHub Pages โดยไม่ต้องมี backend) — หน้าทดสอบเดิมย้ายไปที่ `test.html`

> ระบบนี้ **ไม่ใช่การขออนุมัติงบ** — งบได้รับอนุมัติมาแล้ว ระบบใช้ **ตรวจสอบ (verify) ว่าใช้ถูกตัวงบ**
> และให้ผู้ใช้งบรู้ว่างบของตนเหลือเท่าไร

ใช้เมนู **"เข้าใช้งานในฐานะ"** มุมขวาบนเพื่อสลับผู้ใช้ตัวอย่างตามบทบาท

| บทบาท | ทำอะไรได้ |
| --- | --- |
| การเงิน | บันทึก/แก้ไขงบลงทุน (CAPEX) และงบโครงการ (CBS) ที่ได้รับอนุมัติแล้ว, ตรวจสอบว่าแต่ละรายการใช้ถูกตัวงบ แล้ว *ยืนยัน* หรือ *ส่งกลับแก้ไข* |
| ผู้ขอใช้งบ | เห็นเฉพาะงบของตนเองพร้อมยอด *งบที่ได้รับ / ยืนยันใช้แล้ว / รอตรวจสอบ / คงเหลือ* และยื่นขอใช้งบโดยระบุตัวงบทุกครั้งที่จะใช้ |

### ขั้นตอน
ผู้ขอใช้งบเลือกตัวงบและกรอกรายละเอียด → การเงินตรวจสอบตัวงบ → ยืนยัน (ออกเอกสาร) หรือส่งกลับพร้อมเหตุผล (เช่น ควรใช้งบตัวไหนแทน)

**งบลงทุน (CAPEX)** — งบเป็นวงเงินก้อนเดียว
- ระบุ: สินทรัพย์, จำนวน, อายุการใช้งาน, เลขที่ใบเสนอราคา (ถ้ามี), เหตุผลความจำเป็น

**งบโครงการ (CBS — Cost Breakdown Structure)** — งบแตกเป็นรายการต้นทุน
- ต้องเลือกรายการต้นทุนที่จะใช้ และระบุงาน/งวดงาน; ยอดคงเหลือแสดงและตรวจสอบราย *รายการต้นทุน*

### ยอดคงเหลือ
- รายการที่ส่งแล้วจะ **จองงบ** ทันที เพื่อให้ยอดคงเหลือที่เห็นตรงกับความจริง; ถูกส่งกลับหรือยกเลิกจะคืนยอดอัตโนมัติ
- ระบบไม่ให้ระบุยอดเกินคงเหลือ (กันการกรอกผิด)
- การเงินแก้ไขวงเงินให้ต่ำกว่ายอดที่ใช้/จองไปแล้วไม่ได้ และลบงบที่มีรายการแล้วไม่ได้

### เอกสารผลลัพธ์
เมื่อการเงินยืนยันแล้ว ระบบออก **ใบยืนยันการใช้งบ** เลขที่ `CAPEX-ปี-ลำดับ` หรือ `CBS-ปี-ลำดับ`
พร้อมสรุปยอดงบก่อน/หลังใช้ และผู้ตรวจสอบ — พิมพ์หรือบันทึกเป็น PDF เพื่อแนบกับใบขอซื้อ (PR)

### ข้อจำกัดของต้นแบบ
- ข้อมูลเก็บใน `localStorage` ของเบราว์เซอร์ จึงไม่แชร์ข้ามเครื่อง/ผู้ใช้จริง และไม่มีการยืนยันตัวตน
- ก่อนใช้งานจริงควรมี backend + ฐานข้อมูล, ระบบล็อกอิน, และเชื่อมเลขที่ใบยืนยันการใช้งบเข้ากับขั้นตอนขอซื้อ (PR)
